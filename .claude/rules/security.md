# 安全规则

> **替换占位符**：`⟨App/**⟩` / `⟨Tests/**⟩` 改成你实际的源码与测试目录。

## 凭据

- 禁止在代码中硬编码密钥、API Key、密码、Token
- 凭据存系统钥匙串（Keychain / Credential Manager），**不要**放 UserDefaults / 明文配置文件
- 本地配置（主题、开关、上次选中项）走轻量存储即可
- **仓库配置也要检查**：`.git/config` 里的 remote URL 不要带明文 token

## 网络与第三方

- 第三方能力优先走系统框架，不引入第三方 SDK（R005）
- 需要密钥的系统能力（如天气服务），在应用入口的 `init()` 中设置，**不要**散落在业务代码里
- 引入任何会外发用户数据的能力（AI 规划、分析、崩溃上报），必须同时满足三条：
  1. 默认关闭
  2. 用户在设置页显式开启
  3. 隐私说明里写明"什么数据、发给谁、何时发"

## 用户数据

- 明确写出数据存放位置，并保证这个描述与实际行为一致
- 对外宣称"数据只在本地"时，任何一条外发路径都必须先改文案，再上线
- 删除账号 / 清除数据的入口必须真实可用

## 依赖

- 依赖清单需要人工确认，不跟随锁文件自动升级
- 新增依赖前先确认：能不能用系统能力替代

## 测试代码

- 测试里不要写真实凭据，用固定假值
- 快照 / 日志产物不得包含真实用户数据
