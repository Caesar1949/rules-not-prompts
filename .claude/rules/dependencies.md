# 依赖与工程文件规则

> **替换占位符**：改成你实际工程文件的路径。`paths` 必须匹配真实存在的文件。

## 依赖

- 依赖清单人工维护，**不跟随锁文件自动升级**
- 新增依赖前先问：系统框架能不能做到
- 引入第三方 SDK 需要明确批准（R005）；批准后记录到项目手册的依赖清单
- 不在业务代码里写死版本判断来兼容多个 SDK 版本——升级或降级，二选一

## 工程文件

- 工程文件是**结构化文本**，可以读，但不手改内部字段（R004）
- 在 IDE 内配置依赖；批量结构调整用脚本
- 改完工程文件必须做两件事：
  1. 语法校验（如 `plutil -lint ⟨project.pbxproj⟩`）
  2. 完整构建一次
- 工程文件直接纳入版本管理，**不引入生成步骤**（无 `xcodegen generate`、无额外配置文件）
- 同一项目只用一种包管理方式（R003）

## 新增文件

- 若项目用 file-system-synchronized 目录，新文件自动收纳，无需手工登记
- 若需要手工登记（如资源目录），登记后立即构建验证，确认没有"文件在但工程不认"的情况

## 资源

- 图片 / 字体 / 音效等资源需在工程内真实引用
- 新增资源后构建一次，确认打包产物里能找到

## 版本与签名

- 营销版本号与构建号职责分开：前者给人看，后者给商店看
- 签名配置只在工程设置里维护，不写进代码或脚本
